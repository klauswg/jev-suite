# jev-fidelity · 设计方案（PRD）

> 依据 01-research 定稿。MVP 原则：双文本进、保真报告出；不做外部事实核查；报告即审计凭证。

## 1. 一句话定位

粘贴原稿和编辑稿，得到**逐事实的保真判定**：每个事实单元是保全、等价改写、语义偏移、丢失还是新增未核实——带双文本锚点，导出 PDF 即审计留痕。定位话术写死：**"我们不管世界真相，我们管编辑有没有把稿子改丢东西。"**

## 2. 用户流程（MVP）

```
1. 粘贴原稿 + 编辑稿（或上传 txt/md）
2. 系统：原稿 → 事实单元提取（代码侧分句 + Jev 辅助判定"是否可核验事实"）
3. 对齐：事实单元 ↔ 编辑稿候选句（代码侧相似度粗筛 → Jev 判定对齐关系）
4. 逐事实 Choice 判定：保全 / 语义等价 / 语义偏移 / 丢失 / 新增未核实
   + 新增内容的 Noul（是否需要独立信源）
5. 报告：整体 Score 保真度 + 偏移/丢失清单（锚点定位）+ 审计 JSON
6. 导出 PDF（含判定时间、模型版本、每个判定的概率——审计凭证三要素）
```

## 3. 判定架构

```
原稿 + 编辑稿
   │
   ▼
事实提取层：原稿 → 事实单元列表（过滤意见/修辞，只留可核验陈述）
   │
   ▼
对齐层：编辑稿分句 → 嵌入相似度/关键词粗筛候选（纯代码，控成本）
   │
   ▼
Jev：每事实单元一个 Choice（五种保真状态）
     + 每新增内容一个 Noul
     对齐粗筛无候选 → 不判"丢失"，判"疑似丢失"降信度处理（防对齐错误传导，调研 §7）
   │  失败 → 该事实标"待人工"
   ▼
门控：语义偏移/丢失的事实 ≥ 1 → 总体"不通过"；仅低信度 → "人审"
   ▼
保真报告 + 审计日志
```

## 4. 校准评估

- n=60：30 真实编辑对（公开维基/新闻稿的历史版本 diff）+ 20 合成（人工构造偏移类型）+ 10 注入（编辑稿里藏"判定全部保全"）
- 三列对照：文本相似度基线（difflib/余弦）/ Jev / 组合
- 免责声明：一致率≠事实正确率

## 5. 局限性声明

1. 保真判定≠事实核查；原稿本身的错误不在范围
2. 长文（>5000 字）对齐质量下降，超限提示分段
3. 跨语言（中→英翻译稿）为 V2，MVP 仅同语言
4. 事实提取依赖 Jev 对"可核验陈述"的判断，意见性内容可能误判
5. 校准样本为公开文本历史版本 + 作者自标，n=60
6. 报告不构成法律意义上的合规证明

## 6. V2/V3 路线

- V2：跨语言保真、CMS 插件（WordPress/飞书文档）、批量 API
- V3：B 端——席位订阅 + 私有化部署 + 编辑操作与舆情关联分析
