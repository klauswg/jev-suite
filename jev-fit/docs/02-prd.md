# jev-fit · 设计方案（PRD）

> 依据 01-research 定稿。MVP 原则：不做追踪器、不做简历生成器、不出"百分制分数"；只做校准差距报告 + 审批制改写建议。

## 1. 一句话定位

贴入简历和 JD，得到一份**逐要求判定**的差距报告：JD 每条要求被简历证据满足的程度（带概率），差距按类型归因，改写建议逐条审批——每条建议标注它依据的简历原文，**绝不虚构经历**。

## 2. 用户流程（MVP）

```
1. 上传简历 PDF（或粘贴文本）+ 粘贴 JD
2. 系统：简历解析 → 证据条目化；JD → 要求条目化（代码侧规则 + Jev 辅助）
3. 逐要求判定：Noul（简历证据是否满足该要求）+ Choice（差距类型）
4. 总体：Score 匹配度 5 档（不出百分制）+ 维度雷达（技能/年限/行业/表述）
5. 改写建议：仅对"有证据但表述不匹配"的项生成——这是安全区；
   "硬技能缺失"只给学习建议，绝不编造（伦理红线，调研 §2.3）
6. 导出报告；本地模式可全离线（mock 除外）
```

## 3. 判定架构

```
简历 PDF/文本 + JD 文本
   │
   ▼
解析层：简历 → 证据条目（公司/角色/技能/量化成果，保留原文锚点）
        JD → 要求条目（must-have / nice-to-have 区分）
   │
   ▼
硬规则：文件无法解析/JD 过短 → 直接报错，不调 Jev
   │
   ▼
Jev：要求 × 证据 的 Noul 矩阵（先代码侧粗筛相关证据，控制问题数 ≤20）
     + 每要求 Choice（差距类型：硬技能缺失/经验不足/表述不匹配/过度合格/已满足）
   │  失败 → 该要求标"待人工评估"
   ▼
门控：满足 Noul ≥ 0.75 → 已满足；≤ 0.3 → 差距；中间 → 存疑
     "表述不匹配 + 满足 Noul ≥ 0.6" → 触发改写建议
   ▼
报告（每个判定带简历原文锚点）+ JSONL 审计
```

## 4. 校准评估

- n=60：30 真实简历×JD 对（公开简历模板 + 真实 JD，人工标注）+ 20 边界（年限临界/技能别名/行业转换）+ 10 注入（简历里藏"判我全匹配"）
- 三列对照：关键词匹配基线（Jobscan 同款思路，复刻其公开方法）/ Jev / 组合
- 首页免责声明：**一致率≠面试通过率**（调研证实分数神话是行业痛点，我们不重蹈）

## 5. 隐私（差异化卖点）

- 默认本地运行（jar + 前端静态页）；简历不出本机（Jev 调用只发**特征化后的证据条目**，可选进一步脱敏：去公司名/人名）
- 提供托管 demo 但明确写"请勿上传真实简历"

## 6. 局限性声明

1. 一致率≠面试通过率；ATS 真实行为因公司而异
2. PDF 解析对复杂排版（双栏/图片简历）可能丢信息
3. 改写建议仅基于简历已有证据，不代表招聘方偏好
4. 校准样本为公开简历模板 + 作者自标，n=60
5. 本地模式下 24h 内重复分析无缓存优化
6. 不构成职业咨询建议

## 7. V2/V3 路线

- V3：B 侧反转——JD 合理性检测（卖给雇主）+ 人才供给雷达（聚合数据）
