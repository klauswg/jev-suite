# jev-rental · 调研报告（房源看房前待确认项）

> 调研日期：2026-09-23。结论先行：中国租房投诉三年 14,810 件，「低价引流/图房不符」被 2026 年 4 月暗访证实系统性存在；政府房源核验码只核验**产权维度**（抵押/查封/居住权），**房源描述与现实/常识的语义一致性无人核验**——这是我们的空位。但 B 侧重关系销售、冷启动最慢，优先级 4（最后做）。

## 1. 市场痛点 [已核验]

- 消费保《房屋租赁行业投诉分析报告（2023—2025）》：三年累计投诉 14,810 件，合同纠纷 17.33%、退款 16.01%、押金 12.12%；自如 1,287 件居线上平台首位，贝壳 543 件次之 [搜狐转引]
- 21 世纪经济报道 2026-04 暗访：安居客、58 同城「挂牌 1800 实看 2500」低价引流仍系统性存在，平台以"仅为信息展示"推脱核验责任
- 行业共识判断：「谁掌握线下核验权、谁承担虚假下架成本，谁才更接近真实」——核验权结构是核心矛盾

## 2. 现有核验层 [已核验]

| 层 | 代表 | 核验什么 | 不核验什么 |
|---|---|---|---|
| 政府核验码 | 扬州/合肥/上海等各城市平台 | 产权维度：抵押、查封、异议登记、居住权、交易限制 | 描述是否夸大、图片是否真实、"朝南/近地铁"等声明 |
| 平台机制 | 贝壳楼盘字典等 | 部分字段真实性 | 平台既当裁判又当运动员（投诉数据证实） |
| PM 侧防欺诈（海外） | RentEngine Fraud Guard / Property Shield | 房源被克隆、假租客 | 房东/中介侧的描述失真 |
| 租客侧验证（海外） | Cleared.id Property Check | 电话号码/图片对照欺诈库 | 语义级声明核验 |

**空位确认**：「房源描述的逐条语义核验」（朝南？近地铁？拎包入住？面积与户型图一致性？）无直接命中。政府管产权，平台管字段，没人管**描述与现实的语义差距**。

## 3. 数据源可行性 [部分核验]

- 房源描述文本/图片：用户粘贴或截图上传（MVP 不爬虫，规避 ToS）
- 常识性核验（距地铁距离）：可接地图 API 距离计算，Jev 只做描述理解
- 政府核验码：各城市平台无公开 API，MVP 只做"提示用户去官方核验"的引导链接，不伪造对接

## 4. Jev 适配

- Noul 数组：描述中每个可核验声明一个判定（"描述声称 X，证据/常识是否支持"）
- Choice：风险模式分类（低价引流/图房不符/二房东风险/条款陷阱/无明显风险）
- Score：描述完整度分档（关键确认项缺失多少）
- 输出形态：看房前确认清单（未明确的项 → 自动生成给中介的质询话术）

## 5. B 侧验证

- 长租公寓运营商：机构房东、房源标准化、决策链短——最佳切入点
- 中介品牌总部：门店描述质检看板（哪些门店夸大宣传风险高）
- 监管侧：各地真房源政策持续推进（扬州 2026-05 上线核验功能是趋势证据），但监管销售周期以年计
- 数据资产：「描述 × 现场确认 × 纠纷结果」三元组——哪些描述模式最终引发纠纷

## 6. 风险

| 风险 | 对策 |
|---|---|
| 判定依据不足（描述语义不等于现实） | 输出定位为"确认清单"而非"真假判定"——我们告诉你*该问什么*，不替你下结论。这比竞品诚实，也规避责任 |
| 房源平台反爬/法律 | MVP 纯用户提交，不碰爬虫 |
| B 侧销售周期 | 放最后做，先用 C 侧工具积累描述模式数据 |

## 7. 结论

做，但放四项目最后。MVP 最轻：「粘贴房源描述 → 逐条声明提取 → 可核验性分类 → 看房确认清单 + 质询话术」，纯前端 + 单接口，不做账号体系。
