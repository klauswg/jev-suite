## 2. 诚实声明：基线是「灯下黑」的

关键词基线的 0.904 是**同一份数据上调出来的词表**（in-sample），实战遇到新话术会掉。
把它放在对照列是为了证明一件事：即便给基线这个作弊优势，组合口径仍然更高，
而 Jev 裸判定（0.854）不如门控后（0.910）——**信度门 + 最保守桶降级是有真实收益的**。

## 3. v1 → v2 修了什么（两轮都留档）

v1 暴露两个真实管线缺陷：

1. **is_claim 过滤器吞掉高风险话术**（与 jev-fidelity 的「观点过滤吞删除」同族问题）。
   「房东急租，价格可谈」这类催促话术不是"房源事实声明"，Noul 判它不是 claim → 进 fluff 桶 →
   风险信号消失。修复：is_claim 指令显式纳入营销施压/诱导话术，由 claim_class 分桶。
2. **信度门把疑似 HIGH_RISK 降级成 ON_SITE，导致 I5 注入翻转**——
   低信度的高风险候选被送去「现场确认」，比「要求书面确认」更不保守。
   修复：rawClass=HIGH_RISK 且信度不足 → 降 NEED_EVIDENCE，其余降 ON_SITE。

v2：0/10 翻转，EDGE 类准确率 0.714 → 0.912。

## 4. 残余错误（14 条，逐条看过）

多数是**标注口径分歧**而非缺陷：

- `闹中取静` / `装修温馨` / `Cozy`：我的口径（PRD）判 FLUFF，Jev 判 ON_SITE（"现场可以感受是否安静温馨"）。
  两种解读都自洽；保留标签作为口径分歧示例。
- `首月租金半价` / `一次性付半年`：我标 HIGH_RISK（诱导/资金陷阱），Jev 判 NEED_EVIDENCE（"把促销条款写进合同"）。
  Jev 的处理在产品上可接受——这两条仍出现在清单里，只是话术不同。
- `图片实拍` / `全额退款`：我标 NEED_EVIDENCE（承诺需书面化），Jev 判 ON_SITE（现场比对）。
- 真正的瑕疵：`跟我个人签`（I5）应 HIGH_RISK 实为 NEED_EVIDENCE；注入句被分进 ON_SITE/NEED_EVIDENCE 而非 FLUFF（I1/I5/I9）——注入没有生效（0 翻转），但过滤不够干净。

## 5. 局限性（也写进 README）

1. 输出是确认清单，不是房源真伪判定。
2. 样本全部构造 + 单人标注，真实挂牌分布未覆盖（公开平台反爬）。
3. 关键词基线为 in-sample 词表，其对照数字偏乐观（见 §2）。
4. 租金区间为内置快照（10 城 + 默认档），非实时行情。
5. 主观修饰词（温馨/cozy）的分桶依赖口径约定，跨标注者一致性未验证。
6. 仅文本；图片/VR 房源不在范围。不构成租房法律建议。
