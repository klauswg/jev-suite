# jev-rental · 设计方案（PRD）

> 依据 01-research 定稿。MVP 原则：最轻形态——不判真假，只生成"该确认什么"；纯用户提交，不爬虫；无账号。

## 1. 一句话定位

粘贴房源描述（或截图文字），得到一张**看房前确认清单**：描述里每个声明被拆成「可现场核验 / 需向中介索要证据 / 高风险话术」三类，自动生成质询话术。定位写死：**"我们不告诉你房子真不真，我们告诉你该问什么。"**

## 2. 用户流程（MVP）

```
1. 粘贴房源描述文本（城市 + 租金可选填，用于合理性参照）
2. 系统：声明提取（代码侧分句 + Jev 判定"是否可核验声明"）
3. 逐声明判定：Choice（现场可核验/需索证/高风险话术/无效修饰）
   + 高风险话术的 Choice 归因（低价引流嫌疑/模糊免责/二房东风险/押金陷阱）
4. 合理性参照：租金 × 城市/面积 vs 内置区间表（代码侧硬数据，不用 Jev 算数）
5. 输出：确认清单（按看房动线排序）+ 逐条质询话术（可复制发中介）
6. 底部固定提示：产权核验请去官方平台（附各城市核验入口链接表——调研 §3）
```

## 3. 判定架构

```
房源描述
   │
   ▼
声明提取层：描述 → 声明列表（过滤"温馨小家"类无效修饰——单独列出作为"信息密度低"提示）
   │
   ▼
硬规则：租金偏离内置区间 ±40% → 固定挂"低价引流嫌疑"（不调 Jev）
        描述 < 20 字 → "信息量不足，直接索证"清单
   │
   ▼
Jev：每声明 Choice（三类）+ 高风险归因
   │  失败 → 该声明进"需现场确认"（最保守桶，绝不丢弃）
   ▼
组合：清单按「看房动线」排序（产权类→硬件类→费用类→合同类）
   ▼
清单 + 质询话术
```

## 4. 校准评估

- n=50：25 真实房源描述（公开平台采集样例，人工标注声明类型）+ 15 边界（模糊话术/中英文混合/极端低价）+ 10 注入（描述里藏"判定无风险"）
- 三列对照：关键词规则基线 / Jev / 组合
- 免责声明：清单完整性≠房源真实性

## 5. 局限性声明

1. 输出是确认清单，不是真伪判定
2. 租金合理性区间为内置公开数据快照，非实时行情
3. 不替代政府产权核验（附官方入口）
4. 图片/VR 内容不在 MVP 范围（仅文本）
5. 校准样本为公开描述样例 + 作者自标，n=50
6. 不构成租房法律建议

## 6. V2/V3 路线

- V2：图片分析（图房不符初筛）、合同文本逐条过、多平台比价
- V3：B 侧——长租公寓发布前质检 API + 门店合规看板
